# Whole-cache cleaning for regenerable package-manager caches (issue #41)

Issue #41 asked us to reinstate `uv\cache` and a Maven cache as cleanable `Target`s after they were
withdrawn in `ca2004d` because the original entries used `scope = "contents"` with a 24-hour
Minimum Age. That mechanism deletes package contents **per file, by age**: it can leave a partially
cleared cache, and for uv it can corrupt the hardlink/archive index when files are still in use.

## Decision

We add a second cleanup scope, `Scope::WholeCache`, and reinstate two Tier 2 / Caution `Target`s:

- `uv-cache` → `FOLDERID_LocalAppData\uv\cache`. Fully regenerable by uv.
- `maven-wrapper-dists` → `FOLDERID_Profile\.m2\wrapper\dists`. Downloaded Maven distribution
  archives, fully regenerated by the Maven Wrapper.

A whole-cache `Target` is scanned into **one** item representing the entire cache root. Its `Clean`
removes the whole directory as one unit: the remover walks and deletes the contents by handle, then
removes the root itself. No Minimum Age is applied to any entry and no per-item deselection is
offered. If the root cannot be fully cleaned, the run reports Skipped/aborted rather than a partial,
age-filtered cache.

We deliberately do **not** target `~/.m2/repository` itself. It mixes downloaded dependencies with
locally installed artifacts (`mvn install`) that cannot be re-downloaded; deleting it wholesale
would irreversibly destroy them. Excluding the local repository entirely and scoping the cleanable
Target to the regenerable wrapper-download cache satisfies "never delete individually installed
artifacts" without introducing fragile per-artifact classification. The local repository remains a
display-only Knowledge Base annotation.

A tool-driven clean (`uv cache clean`, or a Maven clean that reliably excludes locally installed
artifacts) would be an equally safe alternative within this scope; we chose native whole-directory
removal so the operation stays inside the existing ID-only IPC, handle-based remover, and journal,
with no external process execution.

## Safety invariants preserved

- Deny-by-default: both are explicit Allowlist entries; build-time lint still rejects `**`,
  wildcards in the final segment, Protected Path overlap, and duplicate/overlapping roots.
- `whole_cache` scope **requires `min_age_hours = 0`** in the lint; per-file age-based deletion of
  package contents is structurally impossible for these Targets.
- Protected Paths, Link Points (unlinked, never followed), cloud placeholders (always Skipped),
  leaf scoping, moment-of-deletion handle revalidation, and the 120% circuit breaker are unchanged.
- The bridge detects whole-cache items from the Allowlist itself
  (`scanner::is_whole_cache_target_id`), so no target ids are duplicated in the shell.

## Consequences

- A whole-cache selection is all-or-nothing; users cannot cherry-pick individual files.
- Cleaning a cache forces re-download on next use (risk `Caution`, Tier 2).
- Adding a new whole-cache Target requires an allowlist change plus an audited rationale.
